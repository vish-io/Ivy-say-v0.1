# Security and trust boundaries

Ivy Say is an unsigned MVP, not a security-certified product. Do not use it as an autonomous agent or with sensitive accounts without an independent review and testing.

## Dictionary, selection and snippets

When personal words are enabled, a whole-term, 160-character maximum vocabulary hint is sent to both Whisper and the formatter. The formatter receives it as XML-escaped untrusted spelling hints; prompt injection remains possible. Explicit aliases run locally before formatting. The encrypted personalization store is cached in memory for the session. The explicit Ctrl+Alt+Win+D shortcut asks Windows UI Automation for the currently focused control's selected text only, rejects password controls, fails closed when selection is unavailable or focus changes, and asks for confirmation before storing it. It does not monitor keystrokes or use the clipboard. Accessibility providers are external and can misreport controls; use the feature only in trusted applications. Selection text appears in the confirmation dialog. The shortcut can conflict with another app. Snippets are encrypted and off by default; exact matches skip AI formatting but still pass the ordinary insertion/review checks. Expansions can contain commands, so review them before enabling this feature or inserting into sensitive destinations.

## Application context

The app-context setting is on by default for new installations. When enabled with AI formatting, Ivy Say captures the foreground window and process ID when the shortcut is received and looks up only the process name asynchronously. If available and safe, the name is sent to Groq with the transcript; no window title, path, document, screen contents or field contents are collected for this feature. The lookup may be omitted if unavailable or not ready, without delaying formatting. A browser name does not identify the current site. Process names are untrusted hints and the model may still misuse them. Groq's data policies apply to app names too. This feature never relaxes insertion or review protections.

## Prompt injection and generated text

The transcript is XML-character-escaped inside transcript tags in a user message separate from the formatter's system instructions; the API request itself is JSON-encoded. The prompt restricts it to editing and explicitly forbids answering questions or generating code from requests, including in Code mode. The formatter has no tools or ability to run code. JSON encoding protects the API message structure and XML escaping prevents literal transcript tags from breaking the wrapper, but neither protects the model from instructions inside the data. These are mitigations, **not** guarantees: a model can still obey, hallucinate, or alter text. Treat both transcript and model output as untrusted, and review before sending, executing, or relying on them.

Ivy Say checks the foreground window and detectable Win32 focused control at insertion. Settings offer three security levels:

- **0 · No restrictions:** no automatic content, terminal, or unverified-target review, including unsafe controls and multiline output. Commands or line breaks can execute actions or send messages. The original foreground window and any detectable focused control must still match; operating system failures can still prevent insertion. Review-window copying is not blocked for unsafe characters in this mode.
- **1 · Guarded review:** known terminal processes, unverified targets, and output with line breaks, tabs or unsafe characters are held for manual review.
- **2 · Review every dictation:** all output is held for manual review.

Some IDE terminals, browsers, remote desktops, password fields, inaccessible controls, app-internal focus changes, and renamed terminal processes cannot be reliably recognized. Focus can also change between checks. Guarded mode is a best-effort blocklist, not a sandbox or allowlist. For sensitive work, use level 2 and check the destination and content. Pasting into a terminal can execute commands, especially with line breaks. Clipboard history and other applications may read copied content.

In guarded and review-everything modes, unexpected control characters, bidirectional override/isolate characters, and malformed surrogate pairs are not automatically inserted or copied by the app; the user can review/edit the result. Other visually deceptive Unicode and malicious instructions can still pass through. Level 0 does not apply this check. The review window is local and is not automatically saved by Ivy Say.

In the default streaming-preview mode, fragments are shown in the pill but are not inserted until the response completes and the selected insertion policy has been checked. An explicitly enabled direct-streaming mode (level 0 only) types unvalidated partial model output immediately; no automatic rollback is possible. It is unsafe for terminals, sending messages, or sensitive applications. A failed stream after insertion begins holds the partial text in memory for manual recovery without inserting it again or trying another model. Before direct insertion, eligible provider errors may trigger fallback requests to the other GPT model and, if eligible, a final preview model. Third-model pricing and availability can differ. Focus checks are best-effort and do not guarantee safety.

## Provider and local data

API requests use HTTPS with standard certificate validation, no automatic redirects, a shared connection pool, bounded recording size, response-size limits (256 KiB), and bounded request times including reading the body. Error bodies are not displayed. Prompt injection is not prevented by these network bounds. Groq receives recorded audio and transcripts; review its terms and retention policies.

The Groq key and optional personal vocabulary/corrections are protected with DPAPI bound to the Windows user account. It is not a defense against malware already running as that user. General spelling hints are unencrypted in `preferences.json` and sent to Groq. Transcript history and recordings are not intentionally written to disk unless encrypted history and audio retention are explicitly enabled. Daily word counts and recording durations are stored unencrypted as local aggregate statistics and can be cleared in settings. Windows clipboard history, paging, crash dumps, target apps and external software can retain sensitive data. Avoid dictating secrets into untrusted apps.

## Remaining release work

The cloud tests use fake HTTP responses and unit-test insertion decisions; they do not validate actual terminal detection or UI behavior. Before release: run the Windows manual checklist, test cross-process focus and terminals/IDEs/RDP, evaluate adversarial dictations with the live model, benchmark latency, audit and pin dependencies and build provenance, conduct an independent security review, sign installers and updates, and design a secure update mechanism and vulnerability disclosure process. No defense prevents all attacks or guarantees zero latency overhead.

Background chunking, enabled by default, sends completed audio segments to Groq while recording is still active once the threshold is reached. Disable it in General settings to defer audio uploads until stopping. Multiple uploads and a possible full-recording retry can increase provider retention exposure and quota use. Audio remains in process memory unless optional encrypted audio history is enabled; OS paging and crash dumps are outside this guarantee. Optional Opus is lossy, not a privacy or encryption feature.

When comparison is enabled, the original recorded WAV is retained in memory until the comparison window closes, for optional local playback. Clicking play sends it to the default Windows output device, where others nearby may hear it. The comparison feature itself does not write it to disk, but optional encrypted history may do so. OS paging, dumps and output-device behavior are outside this guarantee.

Ivy Say can dictate while Settings is open. For editable fields within its own Settings window, WPF controls share an HWND, so the app additionally checks that the same editor remains focused. It does not permit dictation into the API key field or non-editable settings controls. An in-progress recording uses the preferences and key captured at start; removing or changing the saved key affects subsequent dictations, not a request already in progress. The key remains in memory for the in-progress request, never intentionally written in plaintext.

## Quick Notes and style modes

Quick Notes requires explicit enablement and a user-chosen folder, and appends plaintext with timestamps. Folder ACLs, backups and cloud sync may expose notes; no encryption or automatic desktop fallback is provided. Audio and transcription are still sent to Groq. A failed append may be partial and is not automatically retried. Concise and structured modes may alter wording or omit important details despite prompt instructions, so review output. Sound cues are opt-in and may be recorded by the microphone.

Completed non-streaming output is submitted as one Unicode SendInput batch after the existing target and policy checks; this does not use the clipboard. Focus can change after the check or while Windows processes the queued events, and the target may process or reject them differently. A partial acceptance is treated as an uncertain insertion and is not retried automatically. Direct streaming remains incremental.

Question/instruction-like transcripts detected by a simple English regex are buffered even in direct mode. All buffered formatter output is checked for some suspicious additions, lost negation and apparent answers; flagged output gets at most one stricter formatter retry. If the retry fails or is flagged, minimally edited transcript text is used instead. This is a heuristic, not an injection detector: attacks, other languages, hallucinations and false positives remain possible. Direct streaming for unrecognized content remains unsafe and can type before validation.

Network pool recovery replaces the handler after address changes or transport errors for future requests, but retains old clients until their in-flight requests finish; it does not disable TLS validation or enable redirects. It does not automatically retry an individual transcription or insert a response twice. Existing chunking may still retry the complete recording after a failed chunk, as documented.

Correction learning is separately opted in and off by default. It uses UI Automation to read bounded text around a caret in the same foreground control before and briefly after an insertion, verifies the original insertion, and checks again about 25 seconds later. Password and unknown password states, unstable focus, mismatched controls, ambiguous anchors and unsupported providers are skipped; accessibility providers can misreport sensitivity or hang. Only candidate words from narrow single-word edits are retained in the existing DPAPI-protected personalization store, not the surrounding snapshots or recorded audio. Candidates can be removed in My words and are sent as bounded Groq hints when enabled; they are not forced substitutions. Turning the option off stops future capture and hint use but does not delete stored candidates. Settings and new dictations invalidate pending observations. Direct streaming, snippets, Quick Notes and failed/protected output are not observed. No general keyboard listener or clipboard access is used for learning.

App-specific style learning is independently opted in. It reuses the bounded recent-insertion UI Automation checks and stores only normalized process names and bounded aggregate signals for period and list-layout edits in the existing DPAPI-encrypted personalization store; it stores no observed text, window titles, paths or website names. Once sufficient evidence exists, a fixed allowlisted style hint may be sent to Groq, independent of whether the process-name context option is enabled. It cannot read a website identity from a browser process. Explicit opening commands, dictated punctuation and non-Clean modes skip profile hints. Disabling the feature stops learning and use but does not erase profiles; individual or all profiles can be deleted. Formatting models may still ignore priority instructions or alter meaning. Observation has the same accessibility-provider and password-state limitations as correction learning.

Nearby-text capture and external sharing are separate opt-ins, both off by default. A background UI Automation query reads at most 256 characters around a collapsed caret in the foreground text control. It rejects password or unknown password state, changed focus or caret, missing control handles, unsupported text patterns and invalid/oversized text. A second background read at stop must match the first; no result is awaited on the transcription path. WPF and other apps may expose only a shared window handle, UI Automation providers can misreport sensitivity or focus, and focus can change after the last check. Nearby text and references are not deliberately logged or persisted. Local-only mode applies conservative casing to words already present in complete prose output; no excerpt or derived list is sent to Groq. Explicitly enabling sharing sends the bounded, XML-escaped excerpt as untrusted data to the formatter and fallback/retry requests; the provider receives potentially sensitive third-party content. XML and prompt instructions do not prevent prompt injection or leakage. Direct streaming is disabled for the request when context is sent; the local consistency guard is not a guarantee. Context is not used for Quick Notes, snippets, password fields or Ivy Say settings. The query shares the bounded correction-learning worker, so one hung accessibility provider can stall subsequent lookups without blocking dictation.

Encrypted history is opt-in and audio retention requires separate opt-in. It saves successful normal dictations only, after a password-state and focused-control identity check before and after insertion; UI Automation may misreport password or sensitivity, and no check can rule out sensitive non-password fields. Quick Notes, snippets, failed insertions and review-only output are excluded. Each bounded entry is serialized in memory and protected by Windows DPAPI for the current user before being atomically written under LOCALAPPDATA; no plaintext temp file is created. Filenames are random but filesystem timestamps and sizes remain visible. Expiration is enforced when the app runs, not while it is closed; bounds are 100 entries and 64 MiB. Deletion is logical, not guaranteed secure erasure; backups and cloud sync can retain copies. Disabling retention stops future saves but does not delete old entries. Users can delete an entry, all audio, or all history. Queued saves are invalidated on settings changes and deletion. History is not automatically sent to a provider or used for training. Disk failures or corrupt history can prevent cleanup and saving; history errors do not block insertion. DPAPI is not protection from malware running as the same user, and paging, crash dumps, output devices and UI accessibility are outside the encryption guarantee.

For insertion or Quick Note errors, the latest recoverable text remains in memory and is available only when the user selects Recover last dictation from the pill or tray menu. Automatic review windows are reserved for insertion-policy review. The latest failure replaces the previous recovery; application exit discards it. No automatic repeat of potentially partial input occurs. Hold-to-speak tracks the consumed key through its low-level hook rather than relying on a potentially stale asynchronous key state; the app waits for the trigger and modifiers to be released. Target/focus and OS acceptance checks remain in place in every security mode.

Latest learning check is session-only, contains generic status rather than dictated content, and explains skipped/verified/learned outcomes. A saved word is only a candidate hint, not a forced replacement or a trained model. The checks remain narrow and depend on UI Automation; no real-world success rate is implied.

Windows startup is enabled by default and is configured per user under HKCU's Run key, with a quoted path to the published IvySay.exe and a fixed startup argument. No API key, audio, transcript or user-controlled command arguments are stored in that entry. A `dotnet.exe` development host cannot be registered; changing or deleting the executable may break startup until the new copy is opened. Windows, administrator policy or the user can disable startup. The app starts only after Windows sign-in, remains a normal user process, and its ordinary single-instance check prevents duplicate app instances. Startup can be turned off in General settings; installer uninstall removes only the entry pointing to that installation.
